# Merritt’s Auto Recycling — SEO audit and implementation

Audit date: September 25, 2026 (America/Chicago; tool captures extend into September 26 UTC).

Live site: https://merritts-auto-recycling.com/  
Repository: https://github.com/jwillz7667/Merritts-Auto-Recycling.com  
Baseline commit: `762de7f`  
Implementation branch: `codex/seo-audit-metro-coverage`

**Conclusion:** The site has a sound crawlable foundation, but it was understating the business’s service area and publishing internal editorial language to customers. This change improves geographic relevance, useful navigation, search titles, and accessibility. It does not establish a #1 ranking, measured traffic growth, or complete optimization of off-site profiles.

## What was verified on the live site

- Crawled all 19 URLs in the live XML sitemap: all returned HTTP 200 with matching self-canonical URLs, unique titles and descriptions, and one H1 each.
- Robots.txt allows crawling and links to the sitemap. Both files return HTTP 200.
- Tested HTTP and www normalization, trailing-slash normalization, and the legacy `/about-brad.html` redirect. They resolve to the intended canonical destinations.
- An unknown URL returns an actual HTTP 404.
- Marketing content and JSON-LD are available in initial static HTML. LocalBusiness/AutomotiveBusiness, services, articles, and breadcrumbs are already implemented.
- Mobile homepage at 390 × 844 had no horizontal overflow; call/text links and navigation were usable.
- No active GTM bootstrap was present on any of the 19 crawled pages. The source supports `PUBLIC_GTM_ID`, and pushes interaction events to a data layer, but this is not evidence that those events are being collected. Other account-side analytics were not inspected.
- Search results surfaced the homepage. A `site:` search is not a complete index count; actual indexing, keyword positions, impressions, backlinks, and Google Business Profile performance require account data.

## Changes implemented

| Finding | Change |
| --- | --- |
| Coverage limited to Brooklyn Center and Minneapolis despite metro-wide operations | Owner confirmed all Twin Cities metro cities and surrounding suburbs. Updated the service-area hub, homepage, footer, About page, FAQ, and business/service `areaServed` data. Included Saint Paul and representative suburbs on one useful hub. |
| Public text referred to doorway pages, immutable business records, unsupported claims, and schema | Replaced it with information about selling a vehicle, arranging pickup, and contacting the business. |
| Long local and guide titles | Shortened seven titles while retaining location or vehicle-topic relevance and the brand. |
| Generic homepage service links | Replaced “Learn more” with descriptive service-specific links. |
| Weak contextual paths between services and guides | Added crawlable links between relevant service and guide pages, plus local pickup and metro-coverage pages. |
| One fixed sitemap modification date applied to every URL | Removed the unmaintained optional date. Added build checks for duplicate URLs, missing pages, noindex exclusions, self-canonical agreement, and sitemap completeness. |
| Low-contrast card numbers | Darkened the text color to improve readability. |
| Existing browser checks were unreliable | Corrected the stale homepage expectation, a menu locator whose accessible name changes, clean-URL preview serving, and lint exclusion for downloaded browser binaries. |

The actual street address remains Brooklyn Center. No additional storefronts, fabricated testimonials, guaranteed free pickup, guaranteed same-day service, or unsupported prices were added. Existing guide publication dates were retained; no artificial freshness date was introduced.

Google says sitemap modification dates should reflect real significant changes; adding an arbitrary current date would not be appropriate. [Google sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap).

These are lab measurements, not field Core Web Vitals or a ranking score. Local-machine contention and network conditions affect them. Localhost and production performance scores are not directly comparable; this does not demonstrate an 18-point production performance gain.

## Priority work outside this code change

1. **Search Console:** Verify or use the existing domain property; inspect the homepage, core services, and area hub; submit the sitemap if not already submitted. Check indexing exclusions, selected canonicals, manual actions, and Core Web Vitals. Record a 28-day baseline of non-brand queries, clicks, impressions, CTR, and landing pages. No authenticated Search Console data was available in this audit.
2. **Google Business Profile:** Check the real profile’s primary/secondary categories against actual operations and currently available category choices. Check phone, 8 AM–8 PM daily hours, website, and service areas. A service-region statement does not create a local office or guarantee visibility in every suburb. Add genuine business photos and collect honest customer reviews without incentives or selective solicitation. Profile categories and settings were not changed here. [Google local-ranking guidance](https://support.google.com/business/answer/7091?hl=en), [business representation guidelines](https://support.google.com/business/answer/3038177).
3. **Correct inconsistent directory information:** USCarJunker lists 9 AM–8 PM hours, describes replacement-parts sales and free pickup, and surrounds the listing with its own lead-generation phone number. The listing’s direct Merritt’s phone and address match the site. Confirm services before requesting a correction; do not copy directory claims into the website. [Observed listing](https://uscarjunker.com/jy-26799-cash-merritts-brooklyn-center).
4. **Measure real leads:** Configure the existing GTM integration with the correct container, verify GA4 events for call/text clicks and successful form submissions, and distinguish clicks from completed customer leads. Account/container IDs must come from the business. No tracking account was invented or connected.
5. **Build local evidence:** Add owner-supplied pickup photos, documented service examples, and genuinely useful location-specific information. Only create separate suburb pages when there is enough distinctive content to answer customer questions. Use the metro hub as the initial destination for suburb queries.
6. **Patch dependencies separately:** `npm audit` on the unchanged lockfile reported nine advisories: one critical, six high, two moderate. The direct Astro advisory is [GHSA-26w7-cxv4-gfx2](https://github.com/advisories/GHSA-26w7-cxv4-gfx2); review the patched release and transitive dependencies. Package audit severity is not proof of exploitability on this static deployment. Dependency versions were not changed by this SEO patch.

## Validation and release status

`npm run test:all` passed: sensitive-data scan, ESLint, 17 unit tests, Astro type checks and production build, 21-page build validation, and seven browser tests including mobile navigation, metadata, custom 404, and accessibility checks on key pages.

The implementation is prepared on a separate GitHub branch for review. Production has not been updated by this audit. After deployment, recheck live URLs, redirects, schema, the sitemap, and tracking; then compare search performance over subsequent 28-day periods. Google’s local results depend on relevance, distance, and prominence, so no code change can guarantee the highest position in every service category or city.
